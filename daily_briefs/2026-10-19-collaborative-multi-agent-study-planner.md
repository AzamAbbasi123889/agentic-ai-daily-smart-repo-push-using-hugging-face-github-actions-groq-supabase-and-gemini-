# Collaborative Multi-Agent Study Planner

> An agentic web service that composes personalized study schedules by coordinating specialized LLM agents (Curriculum Analyzer, Time Optimizer, Motivation Coach) and lets users track progress through a lightweight UI.

## 1. Problem statement

Students struggle to create realistic, motivating study plans that adapt to curriculum requirements, personal time constraints, and fluctuating motivation. Existing planners are static or single‑agent, lacking dynamic reasoning across multiple dimensions.

### Target users

- University students
- Professional learners preparing for certifications
- Self‑directed hobbyists

## 2. Unique angle

A self‑critiquing multi‑agent orchestration loop built with LangGraph where agents iteratively refine a joint plan, store reasoning traces, and expose them for user inspection—offering transparency rarely seen in personal planning tools.

## 3. MVP features and acceptance criteria

### Generate Study Plan

User submits a course list and weekly availability; the system returns a day‑by‑day schedule with tasks and confidence scores.

- [ ] API returns a JSON schedule covering all submitted courses
- [ ] Total weekly hours do not exceed user‑specified limit (+/-5%)
- [ ] Each task includes a brief rationale generated by an agent

### Progress Tracker

Users mark completed tasks; the system updates remaining workload and re‑optimizes upcoming days.

- [ ] PATCH /progress updates stored state
- [ ] Re‑optimization runs within 2 seconds
- [ ] Adjusted schedule respects updated time constraints

### Agent Trace Viewer

Frontend displays the step‑by‑step reasoning of each agent (Curriculum, Time, Motivation) for transparency.

- [ ] UI shows ordered list of agent messages with timestamps
- [ ] Each entry includes the originating agent name and confidence

## 5. Architecture

FastAPI acts as the gateway, delegating requests to a LangGraph orchestrator. The orchestrator spins up three specialized agents that share a Redis‑backed state store. Persistent data lives in PostgreSQL with pgvector for semantic lookup of course descriptions. React SPA consumes the REST endpoints.

- **API Layer** — Expose HTTP endpoints, auth, input validation
- **Orchestrator Service** — Run LangGraph workflow, manage agent interaction, persist traces
- **Agents (Curriculum, Time, Motivation)** — Perform domain‑specific reasoning using LLM calls
- **State Store (Redis)** — Cache intermediate agent outputs for fast retries
- **Database (Postgres+pgvector)** — Store users, study goals, schedules, and embedding index of course catalogs

### Data flow

1. Client POST /study-goal → API validates → Orchestrator creates workflow → Agents query pgvector for course semantics → Redis caches intermediate results → Final schedule persisted → API returns JSON

## Gemini design review

### Overlap risks

- Standard multi-agent orchestration demo commonly found in LangGraph/LangChain documentation and tutorials.
- Study schedule / task generation is one of the most common LLM toy application ideas.
- Agent division (Curriculum, Time, Motivation) is conceptually arbitrary and could likely be solved more reliably by deterministic constraint solvers combined with a single prompt.
### Suggested improvements

- Incorporate a deterministic constraint solver (e.g., Google OR-Tools or Z3) for time scheduling, using LLM agents only for qualitative curriculum breakdown and motivation adaptation.
- Add two-way external calendar sync (Google Calendar / iCal) rather than treating it as a stretch goal, as standalone scheduling apps without calendar integration suffer high abandonment.
- Implement a concrete automated evaluation benchmark against real syllabus datasets rather than relying primarily on subjective manual Likert ratings.
